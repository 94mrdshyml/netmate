# 60. Posts for subscribers only (2026-10-25)
- Branch / PR: feat/subscriber-only-posts. The owner: "lets work on feeds now. Before that we are missing the option to select the privacy of the posts, all or subscribers only." Stay out of the feed, search and alerts for people who can't see them; no repost or quote; a locked card with a Subscribe button; access ends with the subscription. Mid-session the owner added: on post delete, do a soft delete for all posts.
- Done: the composer shows "Who can see this: Everyone / Subscribers only" for a new post or quote while subscriptions are on and the member has a price. The post carries `posts.subscribers_of` (migration 0024, one added column, so every old post stays public). The one rule `visiblePosts` gained the one condition (yours, or you pay its creator); the access test is one SQL piece (`hasSubscriberAccessSql`) that `hasSubscriberAccess` now also uses, so the two cannot drift apart. Only a profile and the post page ask for the locked card (`visiblePosts(viewer, { locked: true })`), and a locked post is turned into a card with no words, pictures, counts or quote on the server. Replies inherit the creator, so they follow the post. Repost and quote of such a post are refused by the server, and the repost button is not drawn. Someone mentioned in such a post is alerted only if they can read it.
- Soft delete: `deletePost` already only set `deleted_at`, for every post. Nothing changed there; a test now proves it for a subscribers-only post, and the PRD says so in words. The only things that remove post rows are removing a whole account (rejecting a pending sign-up, which has no posts) and the demo-data cleanup. The new column's foreign key cascades only in that account case.
- Tests: `tests/integration/subscriber-posts.test.ts` (20: choosing, who sees it, feed, search, tag search, saved, locked card has nothing in it, post page, like/save/report/repost/quote, ending a subscription in every way incl. grace days and mode change, the two access questions agree, a block, soft delete, replies, alerts); with the rule switched off 10 of them fail. `tests/e2e/subscriber-posts.spec.ts` (choice appears only with a price, locked card at phone width with a 44px Subscribe button, search shows nothing, post page locked with no reply box, paying subscriber reads and replies, ending Polar's subscription locks it again, everything put back). No existing test changed.
- Note for later: the Subscribe words (tax, Polar, name shared) are now one component (`subscribe-offer.tsx`) used by the profile box and the locked card. Prettier is not part of this repo; do not run it over files.
