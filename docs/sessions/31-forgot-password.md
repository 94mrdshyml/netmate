# 31. Forgot and reset password (2026-10-23)
- Branch / PR: feat/forgot-password. Cut from fresh main after #51 (invite by email) merged. Slice 2a of the email work the owner asked for ("do these"): forgot and reset password first, then verification and welcome, then change email (needs an account settings page that does not exist yet).
- Done: when email is set up, sign-in shows "Forgot your password?" to `/forgot-password`; the email carries a link to `/reset-password?token=...`; the new password goes in, every other session of the account ends, and the person lands on sign-in with a "Password was changed" note.
- How: Better Auth makes and checks the one-time token (`requestPasswordReset`, `resetPassword`, 60 minutes, `revokeSessionsOnPasswordReset`). There is no Better Auth HTTP route in the app, so the email carries our own page link built from the token (`sendResetPassword` in `createAuth`, new `CreateAuthOptions`) and the pages call the server API. `src/server/password-reset.ts` has the sender, the request, the token check (`resetTokenIsLive`, a read of the `verification` table) and the reset.
- Privacy and abuse: the answer is the same for a member and a non-member; the email is sent through `waitUntil` (Better Auth `backgroundTasks`), so timing does not tell them apart either. Limits in the exact D1 table: 5 links an hour per address, 20 requests an hour per visitor, and 10 tries with a link per 10 minutes per visitor (keys are salted hashes). The reset page sets `referrer: no-referrer`. Used and expired links read the same ("Link not valid").
- Test-only outbox: the e2e cannot read the fake mail, so there is `GET /api/test-outbox?to=` (`app/api/test-outbox/route.ts`) which answers only when `ENV` is exactly `test` and is a plain 404 anywhere else. The decision is `readOutbox` in `src/email/transport.ts`, unit-tested for every other `ENV` value. The outbox now lives on `globalThis` so every route in the bundle sees one list.
- Tests: `tests/integration/password-reset.test.ts` (26: link emailed, greeting, address cleaned, unknown address same answer and no mail, bad input, not set up makes no token, refused send, no address in stored rows, password really changes, single use, sessions ended, short and long passwords keep the link, six bad tokens, expired link, two at once cannot both use it, the three limits, no address in keys), `tests/email/messages.test.tsx` (+2), `tests/unit/email.test.ts` (+7 `readOutbox`), `tests/e2e/hq.spec.ts` (+3: not available without email; the whole journey through the real pages with the old password dead and the link single-use; a stranger's address looks the same and sends nothing). They live in hq.spec so no extra sign-up goes through the admin's link (session 28); the member is one of its fillers.
