# 32. Photos on posts (2026-10-23)
- Branch / PR: feat/post-photos. Slice 1 of the three the owner asked for after #53 (photos, then repost/quote/bookmark, then hashtags/mentions). The owner also said the member app is the soul and is not mature, so email verification (2b) and change email (2c) are parked.
- Done: a post carries up to 4 pictures. Composer button, previews, per-picture upload with an error and a remove button, pictures-only posts. Posts, replies, profiles and search show the pictures in a flat grid; each opens in full.
- How: migration `0010_post_media.sql` adds `post_media(post_id, position 0..3, key)` with checks on position and on a `posts/` key. `createPost` takes the photo keys, checks they are distinct, at most four and under the author's own `posts/<id>/` folder, and writes the post and the rows in one `db.batch()`. `toPage` now fills photos for a whole page in one query. The action re-checks every key with `isAttachable(..., "post", key)`. `/api/upload` accepts kind `post` (5 MB, same checks as avatars).
- Decision: a post with only pictures stores one space as its text, because `posts_body_length` wants 1 to 280 characters and rebuilding `posts` on D1 would cascade-delete likes, replies and alerts. `toView` trims it, the card hides an empty body. Quote posts will need the same trick or a safe rebuild; decide then.
- Tests: `tests/integration/post-photos.test.ts` (28: order, lists, picture-only, reply, nothing written when the parent is gone, foreign and wrong keys, five photos, the three database checks, cascade, delete, upload type and size, `isAttachable`), unit limit, 3 e2e in `posts.spec.ts` (post with two pictures survives a reload and the image loads; picture-only post and the four-picture cap and remove; a fake picture is refused and blocks Post).
- Notes: PRD 8.2 and the `post_media` row in section 10 updated. No package. The hidden file input is `aria-hidden` so the button is the only control named "Add pictures".
- Open: files are not deleted from R2 when a post is deleted or a picture is removed before posting (a cleanup job is needed, with account deletion). No width and height stored. No alt text yet. Next: repost, quote and bookmarks.
- After privacy and safety (PR 56) merged first: its migration took `0009`, so this one was regenerated as `0010_post_media.sql` (same SQL, journal and snapshot updated, main merged in). CI also failed on `social.spec.ts` because the admin's 10 posts a minute ran out: posts.spec now sends exactly 10 as the admin in a burst of about 17 seconds, and social.spec posts as the admin about a minute later, so a slow or fast machine decided the result. social.spec's `post()` now waits out the limit once if the app says "Too many attempts" and sends again (checked by running posts.spec and social.spec back to back, which trips it on purpose). Its assertions are unchanged. If anything else needs admin posts, join the burst with a member instead.
