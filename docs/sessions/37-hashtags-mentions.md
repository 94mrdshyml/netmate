# 37. Hashtags and mentions (2026-10-23)
- Branch / PR: feat/hashtags-mentions, PR below once opened. Second of the two PRs the owner asked for ("1 then 2"); the first was reposts, quotes and bookmarks (session 36, PR 59). Built on that branch and opened only after it was merged.
- Done: `#tag` and `@name` in a post are tappable. A tag opens `/search?q=%23tag` (Posts tab) and finds exactly that tag. A name that belongs to a person opens their page and sends them a mention alert (the alert icon is an "at sign").
- How: `src/lib/post-entities.ts` parses text into plain text, tags and mentions (pure; joining the parts gives the original back), caps at 10 tags and 10 mentions per post, and reads a lone `#tag` search query (`parseTagQuery`). Migration `0014_tags_mentions.sql`: two new tables, `post_tags` (post, tag, the post's own time; the database checks the tag is 1 to 50 characters; indexed by tag and time) and `post_mentions` (post, person). Forward-only, safe on older instances; old posts have no rows, so they show no links (a backfill was not done: it would need to re-read every post and alert nobody, and can be a later chore). `createPost` extracts the entities, resolves the mentioned names to active members with no block (one query), and writes the post, its tags, its mentions and their alerts in one `db.batch()`; it now sets the post's time itself so the tag rows carry the same time. `hydrate` reads tags and mentions only for posts whose text has a # or an @. `searchPosts` uses `post_tags` for a lone tag. `PostBody` draws links only for tags in `post.tags` and names in `post.mentions`.
- Rules: nobody is alerted twice for one post (a reply's parent author has the reply alert and a quoted post's author has the quote alert, which replaces the mention alert as the PRD says); never an alert for yourself, though your own name still links; the alert is shown only if the reader can see the post (so a private account's mention of a stranger shows nothing and counts nothing); a web address is left alone as a whole; "C#" and "me@example.com" are plain; an 11th tag or mention stays plain text.
- Tests: `tests/unit/post-entities.test.ts` (27: every parsing rule, the cap, round trip, no markup, the tag query), `tests/integration/tags-mentions.test.ts` (19: tags kept lower-cased and distinct, capped, exact search in either case, one-character tag, paging, replies, the visibility rule for private, blocked and deleted; mentions alert once, skip yourself, pending members and blocks, reply and quote exclusions, the cap of 10, hidden for a reader who cannot see the post, gone with the post; database checks and cascade), `tests/e2e/search-tags.spec.ts` (3: links drawn for a real tag and real name only, text unchanged; tap a tag to search that exact tag, a part of a tag finds nothing; tap a name to open the profile). Named so it runs after `posts.spec`; one admin post, no sign-ups (the admin mentions their own name and one that does not exist).
- Not done: links in post text (web addresses stay plain text; the PRD's link previews come later); a suggestion list while typing `@` in the composer; trending hashtags (the PRD says not in v1); the old posts' backfill; tags inside a quoted card (the card is plain text).
