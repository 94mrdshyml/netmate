# 41. Link previews (2026-10-23)
- Branch / PR: feat/link-previews. The owner asked for the link card to show a few seconds after pasting the address, not only after the post is made. Built on top of the composer branch (PR 63, which also touches `composer.tsx` and `rate-limit.ts`), so this PR is opened only after PR 63 is merged, then main is merged in.
- Decision: the card is fetched while typing, not at post time. The server returns the card together with a signed token; the post action saves a card only with a token that verifies (HMAC with a key derived from the auth secret, tied to the member, valid 30 minutes). So a browser cannot make up a card, and the post does not wait on a slow page. Off by default; the admin switches it on in `/hq/services`.
- Done: `POST /api/link-preview`; the safe fetcher in `src/links/` (address rules, DNS-over-HTTPS lookup, every answer checked, manual redirects checked, 3 seconds, 512 KB, HTML only, ports 80 and 443, real domain names only); the page reader (Open Graph first, then title and meta description; plain text only); the token; `post_links` table (migration 0015, forward-only, checks on lengths and https); the card in the composer (with an x, a waiting line, the Post button holding briefly for a card on its way) and under posts; web addresses in post text are now links (found by parsing); the `/hq/services` switch; rate limit 20 per 10 minutes on the exact D1 table.
- How: `createPost` takes the card (code `bad_link` when it does not fit the words or the checks); `hydrate` reads cards per page in one query. The fake fetcher runs only when `ENV` is exactly `test`, and a unit test proves any other value uses the real one.
- Tests: unit for addresses, page reading, fetcher (timeouts, redirects, size, blocked answers), token and card checks; integration for saving, refusals, visibility, removal with the post and the database checks; browser journeys at phone width (off by default, the switch, card within seconds with Post held, remove, unreadable and unsafe links, posting keeps the card and links the address, forged token dropped, turning off). The app build caught a type error in one integration test file; fixed with a tuple type.
- Not done: caching of pages between members, removing a card from an old post, a card for more than the first address.
- Owner to do after deploy: switch on Link previews and Place suggestions in `/hq/services` (both are off by default). GIF search should already be on.
- Spike 6 / risk R10: mitigated, not closed. Workers cannot pin a looked-up address, so a page that changes its address between the check and the visit is the accepted limit.
