# 13. Invite links and sign-up (2026-10-23)
- Branch / PR: feat/invites
- Done: every member gets one reusable invite link, made on first view of Home (`ensureInviteLink`, 32 random base62 characters, at most one active per member by a database rule). `/sign-up?invite=<code>` shows who invited the visitor and the form (first name, last name, email, username, password); a wrong, revoked or ownerless code shows "Invite link not valid" and no form. `signUpWithInvite` writes user, account, profile, invite use and the link counter in one D1 batch. Every statement carries a "link is still live" guard, so a link revoked a moment ago writes nothing. The profile's status is decided inside that batch before the person is counted: the admin's link is unlimited, any other link approves while `uses_count < quota`, otherwise Pending. Approved people are signed in and sent Home; Pending people go to `/waiting` and cannot sign in. Home shows the link with a copy button. PR #27 was verified live first (deploy green, `/` redirects to `/sign-in`).
- Tests: 17 new integration (link reuse and format, unknown/malformed/revoked codes, first 5 approved and 6th and 7th Pending in order, **8 simultaneous sign-ups give exactly 5 approved and 3 Pending**, admin link unlimited, invited_by recorded, approved can sign in and Pending cannot, hash stored and no session left, revoked link writes nothing, unknown link, inactive owner, every invalid field at once, reserved usernames, taken email and username roll back). 4 new e2e at phone width (admin link works and signs the guest in, member link approves five and holds the sixth on `/waiting`, bad link message, field errors and column fit).
- Real problems found by tests: (1) `invite_uses.outcome` is `approved`/`pending` while profile status is `active`/`pending`, so the insert needed a mapping (caught by the CHECK). (2) In Playwright, `browser.newContext()` inherits the project's stored admin login, so a "visitor" was silently the admin; visitors now pass an empty storage state.
- Decisions: the link is created lazily on first Home view, not at sign-up; a Pending member has no link. Email verification is skipped for now (no Resend slice yet), as the PRD allows without a key.
- Open: no admin approvals screen yet, so a Pending person stays Pending until `/hq` exists; no rate limits on sign-up and sign-in (PRD wants the exact D1 limiter); no live username-availability check as you type (the server reports a taken name on submit); no revoke or regenerate of links (comes with `/hq`).
- Next: rate limits (sign-in and sign-up, exact D1 table), then `/hq` with approvals, invites and branding.
