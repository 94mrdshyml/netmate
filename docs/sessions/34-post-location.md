# 34. Place on posts (2026-10-23)
- Branch / PR: feat/post-location, PR below once opened. Owner asked for GIFs on posts and a place on posts with suggestions from OpenStreetMap ("Photon"). Our rule is one PR per feature, so the place is this PR and GIFs are the next one (`feat/post-gifs`).
- Done: a pin in the composer opens "Where was this?" with suggestions as you type (after two letters and a quarter-second pause, up to six, towns and bigger only, no streets). Pick one, or use what you typed. It becomes a tag with an x; Change place replaces it. On a post the place is a muted pin line under the words and pictures (lists, post page, search results). Replies have no pin. The place is plain text, 1 to 60 characters, never coordinates.
- How: `posts.place` (migration `0011_post_place.sql`: one nullable column; the length CHECK is written by hand in the SQL because drizzle would rebuild the whole table to add one, and a rebuild risks cascade deletes on D1). `src/lib/place.ts` cleans and checks the text. `src/places/photon.ts` asks Photon from the server (layers locality, district, city, county, state, country; English; 3 second limit; no cookies; a plain User-Agent) and builds labels like "Bengaluru, Karnataka, India" (repeats dropped, at most 60 characters). `/api/places?q=` needs a signed-in member and the setting on, limits 40 a minute per person (`limitPlaces`), refuses other sites (`Sec-Fetch-Site`), answers `unavailable: true` instead of an error when Photon fails. `createPost` takes the place; the action refuses one when the setting is off.
- The admin switch: setup already asked "place suggestions on or off", but nothing could change it afterwards. `/hq/services` (new, in the side menu) has the switch; it saves at once. The GIF key will join this page.
- Tests: `tests/unit/place.test.ts`, `tests/unit/photon.test.ts` (the Photon request, label rules, every failure mode, the fake only when `ENV` is exactly `test`), `tests/integration/post-place.test.ts` (17: saved and shown in feed, profile, search and replies; trimmed; 60/61 limit; place alone is not a post; hidden with the post; the database CHECK; the 40 a minute limit; the switch), `tests/e2e/search-place.spec.ts` (6: off by default with no pin and a 404; the admin switch; suggestions, keyboard and posting; typed place when "Photon is down", remove, too long; fits a phone, Escape, no pin on replies; signed-out 401 and off again). The browser tests never reach Photon: with `ENV=test` a small fixed list answers, and the word "offline" pretends Photon is down.
- Decisions: the place is its own plain line, not a link, and not searchable. Typed places are allowed on purpose (Photon can be down or miss a village). The suggestion route and the post action read the setting straight from D1, because a route keeps its own copy of the settings cache and a switch just changed would look off for up to 30 seconds. The e2e spec is named `search-place` so it runs after `posts.spec` (which sends exactly 10 admin posts in a burst) and uses only two admin posts and no sign-ups (the admin link's 20 sign-ups are used up, see session 33).
- Not done: the profile "City or country" field (PRD 8.4) can reuse `/api/places` and the picker; deleting a post does not clear anything extra (the place is a column on the post). Klipy and GIFs are the next PR.
- Next: GIFs on posts (`feat/post-gifs`): the phone talks to Klipy directly (owner's choice, session 34); `CLAUDE.md` rule 3 is changed to say so.
