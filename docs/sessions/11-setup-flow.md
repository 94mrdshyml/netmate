# 11. The /setup flow (2026-10-23)
- Branch / PR: feat/setup-flow
- Done: `/setup`, the first-run flow, in six mobile-width steps (token, admin, name, look with a live light and dark preview, optional Resend key, optional extras). `completeSetup` writes the admin user, credentials, profile, instance row and encrypted keys in one D1 batch; the instance row goes first and its fixed key is the one-time claim. The setup token is checked first in constant time; `/setup` refuses to run unless `SETUP_TOKEN`, `AUTH_SECRET` and `SETTINGS_ENCRYPTION_KEY` are 32+ characters, and lists which are missing (never values). Resend keys are checked with a real call. On success the admin is signed in (Better Auth `nextCookies`) and lands on Home. A route group `(app)` sends every other page to `/setup` until setup is done; `/setup` returns 404 afterwards. The deploy job now sets the three Worker secrets from GitHub secrets of the same name and the smoke test accepts the setup page on a fresh instance. `.dev.vars.example` added. Default avatar style is now `initials` (the old "Cameo" is not a known DiceBear style).
- Tests: 662 unit (validation incl. cross-field rules, constant-time compare, Resend check) and 55 integration (success, hashed password signs in, token refusals, missing deployment secrets, every validation error, second attempt refused, two simultaneous attempts leave exactly one winner and no leftovers, full rollback on a failing write, taken email, no database errors echoed, Resend rejected/restricted/unreachable, one admin). E2E (real browser, phone width, fresh empty database each run): redirect to /setup, wrong token, per-step errors, preview and colour adjustment notice, the full flow through to a signed-in home with the chosen name, `/setup` 404 afterwards and for a stranger.
- Real problems found by tests: (1) Zod skipped cross-field rules when another field was invalid, so people would fix one error and hit the next; validation now reports everything at once. (2) The loser of a simultaneous setup got "failed" instead of "already set up" because it hit the one-admin rule before the instance row; the instance claim is now the first statement and both conflicts map to "already set up". (3) The guard hook blocks any command line containing both "wrangler" and "secret", even inside text; noted in CLAUDE.md.
- Decisions: logo and favicon upload moves to `/hq` (it needs a session); setup uses the built-in ones. Font and avatar style are chosen from short lists until the Google Fonts search arrives with `/hq`. e2e never reuses a server: it resets the database, applies the migrations and starts fresh every run.
- Open: add GitHub secrets `SETUP_TOKEN`, `AUTH_SECRET`, `SETTINGS_ENCRYPTION_KEY` (each 32+ characters) for the live deploy to be able to run setup; until then the live /setup page lists what is missing. There is no sign-in page yet, so a signed-out admin cannot get back in until the next slice. The default font is named but no font file is loaded yet (falls back to system-ui).
- Next: sign-in, sign-out and the invite sign-up with approvals.
