# 21. /hq logo, favicon and font hosting (2026-10-23)
- Branch / PR: feat/hq-logo-favicon-fonts
- Before this: PRs #37 (branding) and #38 (avatars seeded by username) are merged and live.
- Done:
  - Logo and favicon upload in `/hq/branding`. `POST /api/upload` takes kinds `logo` and `favicon`; only the admin may use them (everyone else gets 404, signed out gets 401). `src/storage/brand-files.ts` checks size (1 MB), the file's own bytes (PNG or SVG), PNG size (favicon square and at least 512 px) and refuses, never cleans, any SVG that has a script, event handler, link, embedded page or picture, style block or entity. The key is checked again when attached (`isBrandFileAttachable`); a replaced or removed file is deleted after the row points at the new one.
  - `/media/[...key]` now also serves `instance/` and `fonts/`, each only as its stored type (PNG or SVG; woff2).
  - Logo shows beside the name (sign-in, sign-up, waiting, top bar). Tab icon is the uploaded favicon, or `/brand-icon`, an SVG drawn from the name's first letter and the brand colour.
  - Font hosting: new `fonts` table (migration `0005_fonts.sql`, plain CREATE TABLE). `hostFont` fetches Google's stylesheet for the listed family only, keeps latin and latin-ext for weights 400, 500, 600 and 700, accepts only woff2 files from `fonts.gstatic.com` up to 600 KB, downloads each distinct file once (variable fonts share one), writes rows only if every file was stored, and removes stored files on any failure. `@font-face` rules go in front of the theme CSS (`fontFaceCss` re-checks every key and range). Fonts are read with the instance settings, so one 30 second cache covers both.
  - `saveBrandingForm` saves fields, logo, favicon and font. A bad file key stops the whole save before anything is written. A font download failure still saves the rest and returns a warning; saving again retries.
- Tests: 36 unit (SVG refusals, PNG size, key shapes, CSS parsing and injection), 35 integration (`tests/integration/brand-assets.test.ts`, with a fake Google), 6 new e2e in `hq-branding.spec.ts`. The unit tests caught a real hole: `<use/>` slipped past the SVG check (fixed). Real Google output was parsed once by hand for Inter, DM Sans, JetBrains Mono and Lora (8 faces and 2 files each).
- Local note: the full e2e suite at 4 workers can fail `theme.spec` or `hq.spec` because specs in different files change global instance state at the same time (font, quota, name). With 1 worker, like CI, all 67 pass. Not a product bug; same cause as the earlier hq.spec timeouts.
- Open: the e2e font test accepts both outcomes (downloaded, or warning with fallback) because a run may have no internet; the download itself is covered by the integration tests with a fake Google. Emails need a PNG logo (an SVG logo has none yet), which comes with `/hq/email`. Only latin and latin-ext scripts are hosted, so other scripts use a fallback font. The font list is still the short list.
