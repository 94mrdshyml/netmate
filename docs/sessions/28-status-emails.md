# 28. Sign-up status emails (2026-10-23)
- Branch / PR: feat/status-emails. Cut from fresh main after #46 (React Email) merged and deployed. The owner chose "slice 1, then slice 2": this is slice 1 (pending, approved, rejected); verification, reset and welcome are slice 2.
- Done: three emails through the shared branded layout. `src/email/messages.ts` holds the words (subject plus heading, paragraphs and button for each), `src/server/status-emails.ts` finds the people and sends (`emailAdminOfPending`, `emailApproved`, `emailRejected`, `pendingContact`), `src/server/mail-context.ts` gathers transport, encryption key and site address from the Worker env, `siteUrl` in `src/email/template.ts` builds button addresses.
- Wired in the actions, not in the domain functions, so `signUpWithInvite`, `approvePending` and `rejectPending` keep their return values and tests. The sign-up action emails the admin only when the new account is Pending. The approve and reject actions read the person's address first (a rejection deletes the account), then send only if the decision really happened (`result.ok`), so a repeated click sends nothing.
- Never blocks: no email set up means skip (one cheap read, no rendering); any failure inside is caught, and a refused send is recorded for `/hq/email` like every other send. The send is awaited rather than left to `waitUntil`, so the outcome is certain in tests; it costs one HTTP call on a Pending sign-up.
- Privacy: the admin email names the applicant and the inviter but never the applicant's address. Subjects are collapsed to one line, so a name with a line break cannot add a header. Names are escaped by React like all other text.
- Tests: `tests/email/messages.test.tsx` (7: copy, missing inviter, no button without an address, instance name comes from the caller, no em dash, `siteUrl`), `tests/integration/status-emails.test.ts` (10: admin email content and address, nothing when not set up, nothing for a non-Pending person, no button without a site address, hostile name, refused send recorded, contact only while Pending, approval and rejection emails, not-set-up skip), `tests/e2e/hq.spec.ts` (3 added: a waiting sign-up, approval and rejection with email set up; a refused sender does not block sign-up or approval and `/hq/email` shows the reason; not set up works as before). The e2e cannot read the fake outbox from the browser, so it reads "Last email sent" and the last error on `/hq/email`; contents are covered by the integration tests. They live in hq.spec because that file's member has used its automatic approvals, and a new file that signed members up through the admin link went over its limit of 20 sign-ups per ten minutes for the whole run, breaking search.spec and social.spec.
- Notes: PRD section 7 updated. No migration, no new package.
