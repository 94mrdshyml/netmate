# 40. Live colour for tags and names, and name suggestions (2026-10-23)
- Branch / PR: feat/compose-live-entities, PR below once opened. The owner asked, with link previews (the next PR, session 41): "tags don't [link] (colour) till it is posted. And mentions needs suggestion while typing and colour change while typing."
- Done: in the composer a `#tag` or `@name` is coloured while it is typed. Typing `@` opens a list of people; a tap, or the arrow keys and Enter or Tab, picks one; Escape closes it.
- How: `ComposeField` (new client component, used by the composer for posts, replies and quotes) draws the text twice, the real box on top with see-through text and a copy behind it with the coloured parts, kept in line by the same CSS and by copying the scroll position. It uses `parsePostText` (the rule that decides what the saved post links), so colour means "this will be a link": a tag with a letter or number, a name of username shape, ten of each, nothing in an email or web address. A name nobody has loses its colour once `/api/mentions?names=` says so. `mentionAtCaret` (pure, tested) finds the `@name` under the cursor; the component follows the cursor with the browser's `selectionchange` (React's `onSelect` did not fire for arrow-key moves). `src/server/mentions.ts`: `suggestMentions` (username, first name or last name starts with it; exact username, then usernames, then names; people you follow first; never yourself, blocked, or not active; six at most) and `existingMentions` (at most ten). `/api/mentions` needs a signed-in member from this site (`Sec-Fetch-Site`), `no-store`, 120 lookups a minute per person (`limitMentions`), and returns only the six fields a mention needs (no email or bio).
- No migration.
- Tests: `tests/unit/post-entities.test.ts` (+5 for `mentionAtCaret`), `tests/integration/mention-suggestions.test.ts` (12: matching by username, first and last name, order, nothing typed, six at most, hidden people, private accounts, underscore not a wildcard, bad input, only six fields, the existence check, the limit), `tests/e2e/compose-live.spec.ts` (6: colour while typing with only real link-shaped parts, the box shows no text of its own, the copy says what the box says, the copy wraps and scrolls like the box with ten tags coloured and the rest not, a name nobody has loses its colour, the list opens and the keyboard and a tap pick, Enter does not post, Escape closes, no list in an email or web address or after a finished name, the endpoint's rules). The name lists are stubbed in the browser because no other member exists at that point in the suite (the sign-up budget is used up); the real endpoint is tested directly.
- Decisions: yourself is not suggested (but your own name is coloured and links, as before); a mention shorter than 3 characters is not coloured, because it would not become a link; a name that is still being typed is coloured as soon as it has the shape, and is un-coloured only if the server then says nobody has it (one short flicker for a made-up name, and none for a real one).
- Not done: suggestions while typing a `#tag` (the owner did not ask); a coloured copy in the reply box on the post page is included (same component) but was not looked at on a real phone keyboard, only in the browser at phone width.
